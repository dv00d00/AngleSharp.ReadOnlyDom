# Pull request #56: Compact lane review

Reviewed commit: `4e86c68342b1295a7f2c3ecb5ac878514ef97493`

Scope:

- `src/AngleSharp.ReadOnlyDom.Compact`;

- the descendant-chain memoization inherited from `origin/main`.

## Summary

The central cleanup decisions are sound. The Compact Markdown writer was a second opinionated HTML-to-Markdown
implementation inside library code, while the streaming Markdown proxy already demonstrates that use case in a sample.
Removing it avoids exposing the internal arena merely to preserve an example-grade converter.

Collapsing `CompactExtractionValue` to owned storage is also correct. `CompactAggregatePlan.Execute` disposes the arena
before returning, so an arena-backed result could never be a valid borrowed value. The surviving attribute projection
copies with `ToString()`, and normalized text is already produced as an owned string.

The new `Arena`, `Document`, `Parsing`, `Projection`, and `Query` folders make the physical layout substantially easier to
navigate. The remaining work is to make the runtime behavior and public surface match that cleaner shape.

## P1: null selectors silently change projection meaning

Locations:

- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateProjection.cs:29`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateProjection.cs:34`

`FirstNormalizedText(null!)` and `FirstAttribute(null!, "href")` are accepted. Internally, `null` is the sentinel for a
self-projection, so invalid caller input silently becomes a different valid query.

Recommended end state:

- call `ArgumentNullException.ThrowIfNull(selector)` in both `First*` factories;
- retain `null` only as a private representation detail for `Self*` factories;
- add negative tests for both public methods.

## P1: class-token matching does not follow HTML token semantics

Locations:

- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateSelector.cs:55`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.Matching.cs:170`

`ContainsToken` uses `TrimStart()` and `Char.IsWhiteSpace`. HTML space-separated tokens split only on ASCII whitespace:
space, tab, line feed, form feed, and carriage return. The current implementation incorrectly treats NBSP and other
Unicode whitespace as separators.

`WithClass` also accepts a value containing multiple tokens. Such a value compiles successfully but can never match one
class token.

Recommended end state:

- use a single exact `IsHtmlSpace` helper;
- reject empty tokens and tokens containing HTML ASCII whitespace in `WithClass`;
- cover NBSP, all five HTML whitespace characters, and embedded-whitespace input in tests.

## P1: recursive traversals are input-depth dependent

Locations:

- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.Matching.cs:19` (`Visit`)
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.Matching.cs:48` (`FindFirst`)
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.Projection.cs:84` (`Append`)

All three traversals recurse once per tree level. Deep untrusted markup can therefore terminate the process with
`StackOverflowException`; this exception cannot be recovered normally.

Recommended end state:

- use iterative preorder traversal over arena handles;
- use an explicit pooled stack only where the arena's preorder/subtree boundaries cannot express the traversal directly;
- add a deep-nesting test that exercises scope matching, descendant projection, and normalized text.

## P2: descendant memoization allocates on the common path

Location: `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.Matching.cs:83`

Memoization is justified for a chain with two or more descendant axes: different backtracking paths can revisit the same
`(handle, step)` state. It is not justified for a single descendant axis. A normal two-step selector such as
`main >> section` cannot revisit a state, yet the current implementation creates a new `Dictionary` for every matching
rightmost candidate. The many-row benchmark uses exactly this shape and can therefore allocate thousands of dictionaries.

Recommended end state:

- keep memoization for genuinely branching selector shapes;
- compile the number and position of descendant axes once;
- stay allocation-free when fewer than two descendant axes can participate in backtracking;
- prefer an iterative dynamic-programming matcher if it is as understandable and benchmarks better;
- replace the timeout-only regression test with deterministic state/operation accounting.

Decision rule: keep the memoized implementation only where it prevents repeated states. Do not pay for a dictionary on
selectors where repeated states are structurally impossible.

## P2: attribute-only plans still retain text

Locations:

- `src/AngleSharp.ReadOnlyDom.Compact/Arena/Arena.cs:145`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateExecution.cs:62`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.cs:111`

`CompactAggregateRequirements.RetainsText` is computed, but it does not control construction. The presence of a
construction view prevents the normal whitespace-text removal, and `SelectTextValue` accepts every text value even for a
plan containing only attribute projections.

Recommended end state:

- feed the compiled text requirement into the construction view;
- for attribute-only plans, retain only the structural information the HTML tree builder requires;
- avoid payload storage and decoding for text that cannot contribute to a result;
- add an attribute-only benchmark and assert retained text counters/storage remain zero.

## P2: the public family name does not describe the operation

Locations:

- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregate.cs`
- `samples/AngleSharp.ReadOnlyDom.Samples/Program.cs:54`
- `samples/AngleSharp.ReadOnlyDom.Samples/README.md:20`

The API contains no aggregate functions. It performs an EOF evaluation over a temporary construction arena and projects
owned rows. The sample calls this lane `COMPACT STREAMING`, then needs a paragraph explaining that it is not input
streaming.

Recommended pre-alpha naming:

| Current | Candidate |
| --- | --- |
| `CompactAggregate` | `CompactProjection` or `CompactExtraction` |
| `CompactAggregatePlan` | `CompactProjectionPlan` |
| `CompactAggregateResult` | `CompactProjectionResult` |
| `CompactAggregateRow` | `CompactProjectionRow` |
| sample `COMPACT STREAMING` | `COMPACT EOF PROJECTION` |

The exact noun matters less than using it consistently and reserving `Streaming` for the bounded UTF-8 pipeline.

## P2: public surface exposes execution machinery

Locations:

- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateProjection.cs:3`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.cs:44`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateResult.cs:35`
- `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateResult.cs:95`

The public contract currently exposes:

- `CompactAggregateProjectionKind` and projection representation properties;
- `CompactAggregateCardinality`, although callers choose cardinality through `First` or `ForEach`;
- requirements and detailed execution counters;
- `Explain` formatting;
- JSON serialization.

Most of these are implementation or diagnostic concerns. Counters also impose token/node/attribute increments and a
tokenizer middleware on every normal execution.

Recommended end state:

- keep public plan construction, execution, owned rows, and explicit value lookup;
- make projection kind, selector representation, cardinality, and requirements internal;
- make diagnostics explicitly opt-in and use them only in benchmarks/tests until a real external consumer exists;
- move opinionated JSON serialization to a sample or a small optional helper layer;
- do not expose representation enums merely to make objects inspectable.

## P2: result lookup conflates two different states

Location: `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateResult.cs:12`

After ownership collapse, `CompactExtractionValue` is always a string plus an `Exists` bit. The row indexer returns the
same default value when a known field produced no value and when the requested field name was never part of the plan.

Recommended end state:

- prefer `TryGetValue(name, out value)` for unknown-name handling;
- decide whether a projected missing value is represented as `null`, an explicit option type, or a small projection value;
- if the wrapper remains, name it for this projection lane instead of as a general extraction abstraction.

## P2: documentation describes the wrong execution phase

Location: `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregateResult.cs:7`

The documentation says extraction runs during tree construction. In reality, `Evaluate` runs after `ParseDocument`
returns, over the completed temporary arena, immediately before disposal.

Recommended wording: "evaluated at EOF over a temporary construction arena." If projection later becomes event-driven,
that should be a separate measured implementation change.

## P3: rejected rows can perform avoidable projection work

Location: `src/AngleSharp.ReadOnlyDom.Compact/Projection/CompactAggregatePlan.Projection.cs:17`

Fields are projected in output order. An expensive optional normalized-text field can be materialized before a later
required field is found to be missing, after which the entire row is rejected. Repeated fields can also repeat the same
descendant search.

Recommended end state:

- compile a required-field preflight order;
- confirm required targets/values before materializing expensive optional values;
- cache identical selector targets within one scope;
- preserve caller field order only in the emitted row.

## Recommended implementation order

1. Fix null selector and HTML class-token correctness.
2. Remove dead Compact dependencies and stale documentation.
3. Gate or replace descendant memoization and benchmark both common and adversarial selector shapes.
4. Replace input-depth recursion.
5. Make attribute-only plans stop retaining text.
6. Rename the lane and reduce its public surface before alpha.
7. Move serialization and diagnostics out of the normal execution contract.
